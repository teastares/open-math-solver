# 项目概况

本文件维护项目级事实与尚未明确的事项。实现细节以代码、依赖清单和配置定义为准，其信息归属遵循 [知识治理规范](governance.md)。

| 项目事项 | 当前情况 |
| --- | --- |
| 当前阶段 | 正在按用户要求持续迭代，与 HiGHS 在共同精度和资源下对照。已有自主 PDHG、历史搜索、Halpern 与稀疏内点法实验路径，目标尚未达成。默认配置和能力边界见[开发与运行说明](development.md)，每轮实际得失见[实验索引](experiments/readme.md)。 |
| 业务目标与范围 | 构建支持线性规划（LP）和混合整数线性规划（MILP）的通用求解器；长期追求达到或超过 Gurobi 的求解性能。用户要求研究随计算资源增长的性能扩展、集群协同和 GPU 利用，并保留专用计算芯片的长期可能性。此处将 MIP 的首期范围限定为 MILP，非线性扩展尚未提出。 |
| 技术栈与依赖 | 核心使用 C++20，基准工具使用 Python，构建使用 CMake；实际配置以 [CMakeLists.txt](../CMakeLists.txt) 为准，依赖版本、下载地址与校验值统一维护在[依赖锁](../dependencies.lock.json)。 |
| 自主实现边界 | 用户已确认最终自主，初期允许复用开源组件。默认路径由 HiGHS 执行 LP/MILP 求解；可显式选择自主 PDHG 或内点法连续 LP 路径，其 LP 迭代不调用 HiGHS，但命令行输入仍复用其文件解析。内点法复用第三方稀疏排序和分解；算法与依赖边界见设计记录。 |
| 研发与计算资源 | 用户目前尚无团队；已有可用于测试的 CPU 和 GPU 集群。当前先优化本机 CPU，保持后端替换边界。用户允许后续使用 GPU 加速，但对照求解器必须使用相同硬件和公平条件；集群设备型号、规模、互联和可分配预算尚未明确。 |
| 算法选择约束 | 用户要求遵循 Sutton 的通用搜索与学习方向，避免在流程中堆积人工领域知识，允许复用已有的“免费信息”。具体解释、计算成本与验证要求见[设计原则](design-principles.md)。 |
| 构建、运行与测试入口 | [开发与运行说明](development.md)统一维护操作步骤，并链接脚本与测试定义。 |

明确需求或引入实现后，及时更新本文件，不将推测写成已确认事实。
